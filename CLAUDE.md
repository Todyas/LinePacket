# Сетевая RTS — правила проекта

Дизайн: docs/design.md. План: docs/sprints.md. Журнал: docs/DEVLOG.md.
Godot 4, GDScript со статическими типами.

## Как работаем
- Делай только текущий спринт. Сначала план, потом код.
- Без заглушек: механика либо работает по дизайну, либо её нет в коде.
  Тестовые двойники — только в tests/.
- Дизайн неполон или противоречив → выбери простейший вариант
  и запиши в DEVLOG «Вопросы к дизайну». Новых механик не придумывай.
- Конец спринта: scripts/test.sh зелёный → запись в DEVLOG → коммит.
- В git и PR не упоминается Claude: коммиты только от имени владельца репозитория,
  без Co-Authored-By и подписей инструментов.

## Архитектура (не нарушать)
- sim/ — чистая логика: без Node, без float, без Time/OS/randi.
  Случайность — только sim/rng.gd с сидом матча.
- Мир меняется только командами (sim/command.gd), применяемыми на тике.
- Тик 20 Гц. Обход сущностей — в порядке id.
- view/ и ui/ только читают состояние и отправляют команды.
- Числа баланса — только в defs/, не в коде.
- Бот видит только знания своего игрока, как человек.

## Тесты
- Каждое правило — тест в tests/ (свой мини-раннер tests/run_tests.gd,
  GUT не используется: см. DEVLOG).
- scripts/test.sh: все тесты headless + проверка детерминизма
  (один сценарий дважды в разных процессах → одинаковый хеш).
