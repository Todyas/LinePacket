# Спринты MVP

Полный текст плана — в исходном документе «Спринты MVP» (вкладка рядом с дизайном).
Здесь — рабочая копия для репозитория: цели, задачи и «Готово, когда». Порядок строгий: S0 → S8.

MVP — дуэль против бота на одной карте: все механики ядра, туман и скрытность, без заглушек.
Правило «без заглушек»: механика из колонки «В MVP» делается целиком по дизайну; того, что «после MVP», в коде нет вообще.

## Фаза 1 — ядро
### S0. Каркас и детерминированное ядро
Цель: симуляция тикает, принимает команды и одинаково считается дважды, а карта рисуется на экране.
- [x] Проект Godot 4, папки, тесты, scripts/test.sh, docs/DEVLOG.md
- [x] sim/rng.gd — генератор на целых с сидом
- [x] Состояние мира, команды и очередь по тикам, тик 20 Гц, хеш состояния
- [x] Формат карты JSON и карта Дуэли (24 узла, зеркальная, 2 ядра, 4 шлюза)
- [x] defs/ с типами узлов и линков
- [x] Отрисовка графа и камера (перетаскивание, зум)
- [x] Реплей: сид и команды в файл, проигрывание

### S1. Пакеты и потоки
Цель: видимые пакеты бегут по сети, упираются в пропускную способность и теряются в пробках. Первый тип — FLOOD.
- [x] Каналы линка: очередь «пакет, тик входа», ёмкость за тик, задержка, размер
- [x] Очереди на выходных портах с лимитом и дропами; CPU узла и загрузка
- [x] Маршруты: кратчайший по цене (задержка + штраф за загрузку), пересчёт раз в 20 тиков и при смене топологии
- [x] START_FLOW / STOP_FLOW (+ SET_FLOW_RATE для колёсика)
- [x] Отрисовка: MultiMesh, яркость линка по загрузке, перегруз красный, дропы осыпаются
- [x] Ввод: перетащить от своего узла к цели — поток, колёсико — интенсивность
- [x] Оверлей F3

### S2. Экономика и захват нейтралов
- [x] Владение узлами, контроль 0–100 и распад; KEEPALIVE от ядра и ближайших своих машин; контроль 0 → нейтрал
- [x] DATA от каждой своей машины к ближайшему своему шлюзу, байты в банк по прибытии; потолок шлюза
- [x] Локальный буфер с лимитом: копится без маршрута и выгружается, когда маршрут появился
- [x] INIT и шкала захвата нейтрала, соревнование двух потоков; шлюзы захватываются так же
- [x] HUD сверху: банк и доход в секунду; заливка узла — контроль, кольцо — захват
### S3. Агенты, доступ и ПО
- [x] 3 агента на ядре; перемещение как AGENT-пакет по маршруту (стоит в пробках); вход пока только на свои машины
- [x] Очередь из 3 задач с ценой и длительностью из defs: сменить пароль, ключи, поставить ПО
- [x] Модель доступа: слабый/сильный пароль, SSH-ключи, список игроков с доступом
- [x] Слоты ПО и нагрузка на CPU: файрвол, хранилище, ретранслятор
- [x] Карточка узла справа, очереди агентов снизу, клавиши 1–3, кольцевое меню по ПКМ
### S4. Атака и захват чужих машин
- [x] Перегруз CPU: машина «лежит» (не шлёт DATA и KEEPALIVE, ПО не работает, доступ не проверяется)
- [x] PAYLOAD и шкала заражения; антивирус замедляет и сбивает шкалу; 100% → смена владельца
- [x] Подбор пароля INIT-ом (слабый быстро, сильный медленно, ключи — нет); вход агента по доступу или в лежащую машину
- [x] Задачи на чужих машинах: украсть ключ, выкачать буфер, закрепиться; вычистить вирус на своих; старые ключи
- [x] Захват ядра завершает матч, экран итогов; F2 — переключение стороны (только debug)
### S5. Туман и разведка
- [x] Модель знаний в sim на каждого игрока: силуэт (на старте вся карта), снимок с тиком, наблюдение (свои узлы и их соседи)
- [x] Единый API знаний (sim/knowledge.gd): view и будущий бот читают мир только через него
- [x] SCAN: до 3 хопов, снимок цели и её соседей на момент прибытия, возраст в карточке и на карте
- [x] Пакеты видны только на линках рядом с наблюдаемыми узлами; чужие потоки не рисуются
- [x] Маршруты игрока строятся по его знаниям: загрузка невидимых линков ему неизвестна
- [x] IDS как ПО: лог атак (флуд, вирус, подбор доступа, скан) с соседним линком источника
- [x] Лента событий слева (клик центрирует камеру), силуэты и бледнеющие снимки на карте
