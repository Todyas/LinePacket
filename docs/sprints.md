# Спринты MVP

Полный текст плана — в исходном документе «Спринты MVP» (вкладка рядом с дизайном).
Здесь — рабочая копия для репозитория: цели, задачи и «Готово, когда». Порядок строгий: S0 → S8 (MVP, сделан), затем S9 → S15 (поворот к стратегии, редакция 2 дизайна).

MVP — дуэль против бота на одной карте: все механики ядра, туман и скрытность, без заглушек.
Правило «без заглушек»: механика из колонки «В MVP» делается целиком по дизайну; того, что «после MVP», в коде нет вообще.

## Фаза 1 — ядро
### S0. Каркас и детерминированное ядро
Цель: симуляция тикает, принимает команды и одинаково считается дважды, а карта рисуется на экране.
- [x] Проект Godot 4, папки, тесты, scripts/test.sh, docs/DEVLOG.md
- [x] sim/rng.gd — генератор на целых с сидом
- [x] Состояние мира, команды и очередь по тикам, тик 20 Гц, хеш состояния
- [x] Формат карты JSON и карта Дуэли (24 узла, зеркальная, 2 ядра, 4 шлюза)
- [x] defs/ с типами узлов и линков
- [x] Отрисовка графа и камера (перетаскивание, зум)
- [x] Реплей: сид и команды в файл, проигрывание

### S1. Пакеты и потоки
Цель: видимые пакеты бегут по сети, упираются в пропускную способность и теряются в пробках. Первый тип — FLOOD.
- [x] Каналы линка: очередь «пакет, тик входа», ёмкость за тик, задержка, размер
- [x] Очереди на выходных портах с лимитом и дропами; CPU узла и загрузка
- [x] Маршруты: кратчайший по цене (задержка + штраф за загрузку), пересчёт раз в 20 тиков и при смене топологии
- [x] START_FLOW / STOP_FLOW (+ SET_FLOW_RATE для колёсика)
- [x] Отрисовка: MultiMesh, яркость линка по загрузке, перегруз красный, дропы осыпаются
- [x] Ввод: перетащить от своего узла к цели — поток, колёсико — интенсивность
- [x] Оверлей F3

### S2. Экономика и захват нейтралов
- [x] Владение узлами, контроль 0–100 и распад; KEEPALIVE от ядра и ближайших своих машин; контроль 0 → нейтрал
- [x] DATA от каждой своей машины к ближайшему своему шлюзу, байты в банк по прибытии; потолок шлюза
- [x] Локальный буфер с лимитом: копится без маршрута и выгружается, когда маршрут появился
- [x] INIT и шкала захвата нейтрала, соревнование двух потоков; шлюзы захватываются так же
- [x] HUD сверху: банк и доход в секунду; заливка узла — контроль, кольцо — захват
### S3. Агенты, доступ и ПО
- [x] 3 агента на ядре; перемещение как AGENT-пакет по маршруту (стоит в пробках); вход пока только на свои машины
- [x] Очередь из 3 задач с ценой и длительностью из defs: сменить пароль, ключи, поставить ПО
- [x] Модель доступа: слабый/сильный пароль, SSH-ключи, список игроков с доступом
- [x] Слоты ПО и нагрузка на CPU: файрвол, хранилище, ретранслятор
- [x] Карточка узла справа, очереди агентов снизу, клавиши 1–3, кольцевое меню по ПКМ
### S4. Атака и захват чужих машин
- [x] Перегруз CPU: машина «лежит» (не шлёт DATA и KEEPALIVE, ПО не работает, доступ не проверяется)
- [x] PAYLOAD и шкала заражения; антивирус замедляет и сбивает шкалу; 100% → смена владельца
- [x] Подбор пароля INIT-ом (слабый быстро, сильный медленно, ключи — нет); вход агента по доступу или в лежащую машину
- [x] Задачи на чужих машинах: украсть ключ, выкачать буфер, закрепиться; вычистить вирус на своих; старые ключи
- [x] Захват ядра завершает матч, экран итогов; F2 — переключение стороны (только debug)
### S5. Туман и разведка
- [x] Модель знаний в sim на каждого игрока: силуэт (на старте вся карта), снимок с тиком, наблюдение (свои узлы и их соседи)
- [x] Единый API знаний (sim/knowledge.gd): view и будущий бот читают мир только через него
- [x] SCAN: до 3 хопов, снимок цели и её соседей на момент прибытия, возраст в карточке и на карте
- [x] Пакеты видны только на линках рядом с наблюдаемыми узлами; чужие потоки не рисуются
- [x] Маршруты игрока строятся по его знаниям: загрузка невидимых линков ему неизвестна
- [x] IDS как ПО: лог атак (флуд, вирус, подбор доступа, скан) с соседним линком источника
- [x] Лента событий слева (клик центрирует камеру), силуэты и бледнеющие снимки на карте
### S6. Скрытность
- [x] Скрытый PAYLOAD (H): дороже (2 Б) и медленнее; на 100% тайный вирус без смены владельца: наблюдение через машину, отвод части DATA, активация (перехват за тик или отключение ПО)
- [x] Бэкдор: задача агента на чужой машине, вход без пароля, переживает смену пароля и ключей
- [x] Сниффер как ПО: крадёт часть чужих DATA в транзите; банк вора растёт ровно на перехваченное
- [x] Скрытое невидимо без IDS или антивируса; обнаружение идёт со временем по defs; найденное чистится агентом
- [x] События в ленте: «[IDS] найден бэкдор на M7», «[IDS] чужой агент на M7»
### S7. Бот
- [x] BotView: единственное окно бота в мир (топология, знания игрока, свои узлы, банк, агенты, потоки); истина недоступна
- [x] Решения раз в 10 тиков: события IDS → расширение INIT → разведка SCAN → укрепление ПО → защита → атака флудом и PAYLOAD (в том числе скрытым)
- [x] Один профиль характера в defs, без читерства; бот видит только то, что видит человек
- [x] Статистика бот против бота: scripts/bot_stats.sh, длина матча и победитель
### S8. Сборка MVP
- [x] Главное меню: новая игра против бота (сид, сторона), выход; бот ведёт вторую сторону в самой игре
- [x] Пауза (Пробел, Esc), экран итогов: время, захваты, заработанные байты; «ещё раз» и «в меню»
- [x] Подсказки по наведению: узлы, ПО, потоки и типы пакетов, задачи агентов, пункты кольцевого меню
- [x] Баланс по статистике бот против бота (только defs), правки записаны в DEVLOG
- [x] Экспорт Linux и Windows (scripts/export.sh, export_presets.cfg), README с запуском; F2/F3/F4 только в debug

(Подробные задачи S2–S8 — в исходном документе; по мере выполнения переносятся сюда.)

## Фаза 2 — поворот к стратегии (редакция 2 дизайна)

Основание: docs/design.md, редакция 2 («Что изменилось», «Было → стало», вехи R1–R4). Порядок строгий: S9 → S15.
Правила те же, что в MVP: без заглушек, sim без float и Node, числа только в defs, бот видит только знания своего игрока.
Дополнительно для фазы 2:
- После каждого спринта игра запускается и матч против бота играется от начала до конца. Бот осваивает новую механику
  в том же спринте на базовом уровне; тонкая настройка бота и баланса — в S15.
- Что дизайн убирает (ручные потоки, SCAN-поток, захват PAYLOAD-ом), удаляется из кода целиком вместе с тестами и UI,
  а не прячется. Тесты переписываются под новое правило.
- Открытые вопросы редакции 2 решаются простейшим вариантом и пишутся в DEVLOG «Вопросы к дизайну».

### S9. Роли машин (веха R1)
Цель: игрок не тянет потоки, а назначает машинам роли; боевая машина не зарабатывает.
- [x] sim: роль у каждой своей машины и ядра: WORK, CAPTURE (INIT), PRESSURE (FLOOD), INFECT (PAYLOAD), INFECT_HIDDEN, WATCH; цель боевой роли — узел
- [x] Команда SET_ROLE (узел, роль, цель) вместо START_FLOW / STOP_FLOW / SET_FLOW_RATE; старые команды и их код удалить
- [x] Цель боевой роли не дальше 3 хопов от машины (иначе команда отвергается); перенастройка роли 5 с (defs), в это время машина ничего не шлёт
- [x] Интенсивность роли — мощность узла из defs (машина 6/с, ядро 8/с), ретранслятор ×2 боевой роли и ×0,5 «Работы»
- [x] DATA рождает только роль WORK; KEEPALIVE шлётся при любой роли; буфер копится только у WORK
- [x] Роли, у которых цель исчезла (нейтрал захвачен, цель стала своей), сами возвращаются в WORK; машина, сменившая владельца, — в WORK
- [x] WATCH: половина дохода, раз в 10 с снимок узлов в радиусе 2 хопов; SCAN-пакет и SCAN-поток удалить
- [x] Бот: те же решения (расширение, разведка, давление, заражение), выраженные ролями; держит долю машин в WORK из профиля в defs
- [x] UI: перетаскивание от своей машины к цели назначает боевую роль по текущей клавише (Q захват, W давление, E заражение, R тайное заражение, T дозор без цели); ПКМ по своей машине — выбор роли, «Работа» возвращает доход
- [x] Значок роли внутри узла, роль и цель в карточке и подсказке; колёсико интенсивности и X-остановка потока удалены
- [x] Тесты: SET_ROLE, отказ дальше 3 хопов, перенастройка, нет DATA у боевой роли, сумма нескольких машин на одной цели, WATCH обновляет снимки, детерминизм
Готово, когда: удар собирается переводом нескольких машин в «Давление», доход при этом заметно проседает, а матч против бота играется до конца.

### S10. Массовые приказы и читаемость ролей (веха R1)
Цель: роли удобно раздавать пачкой, и по карте видно, где армия, а где экономика.
- [x] Выделение рамкой своих машин (ЛКМ-рамка по пустому месту; сдвиг камеры — средняя кнопка), Shift добавляет к выделению
- [x] Перетаскивание или ПКМ при выделении назначает роль всем выделенным (каждая машина проверяет 3 хопа сама; кто не дотянулся — пишет в ленту и остаётся в прежней роли)
- [x] HUD: доход, «в работе N / в бою M», шкала перенастройки
- [x] Линии от боевых машин к их целям (цвет по роли), видимые чужие роли в зоне наблюдения и в снимках
- [x] Дозор: на карте радиус наблюдения машины в роли WATCH
- [x] Подсказки и README под новое управление
- [x] Тесты view: рамка выделяет только свои, массовое назначение, отказ дальних машин
Готово, когда: собрать удар из 4 машин — две секунды мыши; по карте без карточек видно, что противник снял машины с работы (если их видно).

### S11. Захват агентом (веха R2)
Цель: чужую машину, шлюз и ядро забирает только агент; пакеты лишь открывают доступ.
- [ ] PAYLOAD на 100% больше не меняет владельца: машина «заражена» — ПО защитника выключено, атакующий имеет доступ; вычистка агентом снимает
- [ ] Тайный вирус, активация «Открыть дверь» вместо «перехват» и «отключить ПО»: 20 с ПО выключено и у вора доступ
- [ ] Задача CAPTURE: агент на чужой машине с доступом (подобран пароль, ключ, бэкдор, лежит, заражена, открыта дверь); время и цена по типу узла из defs (машина и шлюз 10 с / 20 Б, ядро 40 с / 100 Б)
- [ ] Пропал доступ — задача на паузе, агент стоит; пока на машине агент владельца, CAPTURE не идёт
- [ ] Задача EVICT на своей машине (5 с): чужой агент уезжает на ядро (20 с); вход своего агента на атакуемую машину
- [ ] Событие владельцу «машина атакована агентом» (без IDS — без источника), с IDS — чей агент
- [ ] Смена владельца только через CAPTURE (и потерю контроля → нейтрал); захват ядра агентом — победа
- [ ] Бот: операция «давление/заражение → агент → захват», защита своим агентом и EVICT; ПКМ-меню и карточка: «Захватить», «Выгнать», прогресс захвата у узла
- [ ] Тесты: PAYLOAD 100% не меняет владельца; CAPTURE без доступа отвергается; пауза при потере доступа; агент владельца блокирует; EVICT; ядро агентом = победа; «Открыть дверь»
Готово, когда: без агента чужую машину не взять, свой агент на месте останавливает захват, а бот берёт ядро агентом.

### S12. Маршрутизаторы (веха R3)
Цель: свичи становятся маршрутизаторами, за которые воюют агенты, и задают территорию.
- [ ] Тип узла ROUTER вместо SWITCH (карта и defs); владение, контроль и KEEPALIVE как у машины; DATA не шлёт, ролей нет
- [ ] Задача агента TAKE_ROUTER (15 с, 30 Б) на нейтральном и чужом маршрутизаторе; на чужой нужен доступ, как у машины
- [ ] Правило владельца SET_ROUTER_RULE: пускать или не пускать чужой транзит; закрытый не пропускает чужие пакеты и агентов (видимый дроп)
- [ ] Маршруты игрока обходят известные ему закрытые маршрутизаторы; незнание — пакеты упираются и дропаются
- [ ] Бот: берёт маршрутизаторы своей половины, закрывает их на границе, пробивает чужие агентом
- [ ] UI: квадрат с владельцем, перечёркнутый закрытый, правило в карточке и ПКМ-меню
- [ ] Тесты: захват агентом, закрытый маршрутизатор режет транзит и агента, обход по знаниям, детерминизм
Готово, когда: закрытый маршрутизатор заставляет пакеты и агентов противника идти в обход.

### S13. Строительство (веха R3)
Цель: сеть растёт не только захватом, а стройкой за байты и время.
- [ ] Команда BUILD: кабель, оптика (между своими узлами или своим и свободным портом своего маршрутизатора), новая машина (на свободный порт своего узла), апгрейд CPU, доп. слот ПО; цены и время из defs
- [ ] Стройка с прогрессом; байты списываются при старте; пока апгрейд — машина на половине мощности; отмены нет (как у задач — простейший вариант)
- [ ] Лимит портов узла; позиция новой машины — детерминированная точка рядом с родителем без наложения (целые координаты)
- [ ] Смена топологии: маршруты и знания пересчитываются (routes_dirty), новые узлы и линки в хеше и реплее; стройку видит тот, кто наблюдает узел
- [ ] Бот: линк в обход узкого места к шлюзу, апгрейд CPU боевых машин, новая машина при свободных портах
- [ ] UI: режим строительства (B), выбор что строить, пунктир и контур с прогрессом
- [ ] Тесты: каждая постройка, лимит портов, отказ без байтов, маршрут через новый линк, детерминизм с постройками
Готово, когда: игрок обходит забитый Wi-Fi своим кабелем и видит рост дохода; построенные узлы захватываются и ломаются как стартовые.

### S14. Большая Дуэль (веха R4)
Цель: карта и экономика на матч в 25–40 минут.
- [ ] Новая карта maps/duel_large.json: 40–50 узлов, зеркальная, домашняя подсеть и 1–2 ничейные у каждого, центр с двумя шлюзами, 2–3 магистрали, 6 шлюзов, свободные порты под стройку
- [ ] Агент-разведчик: узлы, через которые агент проехал, получают снимок; агент наблюдает машину, где стоит, и её соседей
- [ ] Наём агентов HIRE_AGENT на ядре (4-й и 5-й, цена и время из defs), клавиши 1–5
- [ ] Меню: выбор карты (Дуэль, Большая Дуэль), по умолчанию Большая
- [ ] Экономика и распад контроля под большую карту (только defs), записать в DEVLOG
- [ ] Тесты: карта грузится и симметрична, разведка агентом, наём, детерминизм на большой карте
Готово, когда: на большой карте видно подсети и магистрали, а матч против бота не кончается раньше 20 минут.

### S15. Бот под стратегию и баланс (веха R4)
Цель: бот играет операциями, а матч длится 25–40 минут с решениями раз в минуту.
- [ ] Бот: план на минуту (сколько машин в WORK, куда агенты, что строить), операции против одной цели за раз, ответ агентом на захват, блокада маршрутизаторами
- [ ] scripts/bot_stats.sh на большой карте: все матчи кончаются победой, средняя длина 25–40 мин, перекоса по сторонам нет
- [ ] Баланс по статистике (только defs и профиль бота), правки в DEVLOG
- [ ] Экспорт Linux и Windows, README под новые правила
Готово, когда: полный матч против бота на большой карте за 25–40 минут, где решения принимаются раз в минуту, а не каждые пять секунд.
